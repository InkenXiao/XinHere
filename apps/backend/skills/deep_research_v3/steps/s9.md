# S9: 生成结论 + 12 项自检 + 保存输出

## 目标

综合所有论述，生成最终结论，完成 12 项质量自检，保存报告。

## ⛔ 红线

- **12 项自检全部打勾才能交付**，缺一项都不行
- **PDF 与 Markdown 必须成对交付**：只交付 MD 不生成 PDF 视为未完成交付
- 未通过的项目必须返回对应步骤修正
- 报告保存前必须逐项确认

## 操作

### 1. 生成结论

```markdown
## 执行摘要
[3-5 句话核心结论，直接给结论，不给背景]

## 结论与建议
### 核心发现
1. ...
2. ...
3. ...

### 矛盾与分歧（如有）
- 来源 A 认为 X，来源 B 认为 Y → 分析差异原因

### 趋势判断
基于证据的趋势判断（标注置信度）

### 建议与下一步
[可操作的建议，非空泛的"应继续关注"]
```

### 2. 输出 12 项质量自检表

```markdown
## S9: 12 项质量自检

| # | 检查项 | 状态 | 未通过则返回 |
|---|--------|------|-------------|
| 1 | 是否按 s0→s9 顺序完整执行？ | ✅/❌ | - |
| 2 | s0 6要素确认表是否输出？ | ✅/❌ | s0 |
| 3 | s2 反思校验表是否输出？ | ✅/❌ | s2 |
| 4 | 核心数据是否有 3 个以上独立来源印证？ | ✅/❌ | s5 |
| 5 | 推测内容是否标注置信度？事实/分析/判断是否自然行文无冗余标签？ | ✅/❌ | s7 |
| 6 | 找不到的信息是否明确说"数据暂缺"？ | ✅/❌ | s6 |
| 7 | T3-T4 级信源是否未作为核心论点支撑？ | ✅/❌ | s6 |
| 8 | 纵轴叙事是否为故事体（因果链条+时代脉络）？ | ✅/❌ | s7 |
| 9 | 第 4 章（交汇洞察）是否为独立新判断？ | ✅/❌ | s8 |
| 10 | 是否明确指出数据缺口和低置信度结论？ | ✅/❌ | s6/s7 |
| 11 | 是否给出了可操作的建议？ | ✅/❌ | s9 |
| 12 | 报告(MD+PDF)是否保存在正确路径且同名？ | ✅/❌ | - |
```

### 3. 保存报告

保存到 `reports/YYYY-MM-DD-{主题}.md`

### 4. 生成 PDF 版报告

与 Markdown 报告**同目录、同名**（仅扩展名不同）：

```bash
reports/YYYY-MM-DD-{主题}.pdf
```

按以下优先级选择生成方式（找到第一个可用工具即用）：

1. **当前环境的内置文档导出能力**（如 Agent 所在平台自带的 PDF/docx 生成 Skill 或工具），优先使用
2. **pandoc + xelatex**（需指定中文字体，否则中文会变豆腐块）：
   ```bash
   pandoc "reports/YYYY-MM-DD-{主题}.md" -o "reports/YYYY-MM-DD-{主题}.pdf" \
     --pdf-engine=xelatex -V CJKmainfont="Microsoft YaHei" -V geometry:margin=2.5cm
   ```
3. **md-to-pdf / node 工具链**：`md-to-pdf "reports/YYYY-MM-DD-{主题}.md"`
4. **Python 工具链**：weasyprint 或 markdown→html + pdfkit
5. **headless Chrome**：先将 md 转为 html，再
   ```bash
   chrome --headless --print-to-pdf="reports/YYYY-MM-DD-{主题}.pdf" 报告.html
   ```

生成后校验：文件存在、大小 > 10KB（空报告或纯文本伪装的 PDF 会导致自检不通过）。

若所有方式均不可用：**明确告知用户 PDF 无法生成及原因，仅交付 Markdown**，不可假装已生成。此项在自检表中标注 ❌ 并说明。

### 5. 输出摘要

将执行摘要和核心结论发给用户（通过飞书/当前对话）。

### 6. 标记完成（结束）

```bash
bash orchestrator.sh --complete s9 --next done
```
