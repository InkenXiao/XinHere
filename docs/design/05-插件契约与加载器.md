# 05 · 插件契约与加载器

> 依据：dsh-07（owner 隔离/fail-loud）、dsh-12（启动纪律）、dsh-06 D2/D3（preset 锁、
> 重名卫生）；PLAN §1 原则 2、§4.4。

## 1. 业务插件结构（`plugins/<name>/`）

```
plugins/financial-report/
├─ plugin.json          # 清单（§2）
├─ contract/
│  ├─ events.json       # 事件族 payload JSON Schema（单一事实源，进 contracts 流水线）
│  ├─ tools.json        # 工具参数 schema（model_facing 部分）
│  └─ component.json    # 前端组件 props schema
├─ backend/
│  ├─ __init__.py       # export: PLUGIN = PluginBackend(name, tools, router, event_types)
│  ├─ tools.py          # LangChain 工具（@tool，见 §3）
│  ├─ router.py         # 可选：业务 REST（挂 /api/v1/plugins/financial-report/*）
│  └─ models.py         # 业务表（Alembic autogenerate 源）
├─ frontend/
│  ├─ index.ts          # export default ComponentDefinition（{kind, version, match, reducer, component}，04 §7）
│  ├─ FinancialForm.tsx # React 组件（lazy）
│  └─ reducer.ts        # 事件族折叠 reducer（纯函数）
└─ tests/               # 契约测试（回放断言）+ 工具单测
```

前后端同目录但物理部署分离：构建时 backend 打包 `plugins/*/backend`，frontend 构建时
扫描 `plugins/*/frontend` 生成静态注册清单（**M1 不做运行时热插拔**，PLAN §5）。

契约聚合规则：`gen.py` 的 schema 来源 = `packages/contracts/schemas/`（平台核心事件、
通用工具）+ `plugins/*/contract/*.json`（插件事件族/工具/组件 props），两源合并后统一
生成双端类型；跨源 type 重名 = CI 失败（fail-loud，与插件重名卫生同语义）。

## 2. plugin.json 清单格式

```json
{
  "name": "financial-report",
  "version": "1.0.0",
  "domain": "financial",
  "description": "财务指标填报与派发",
  "tools": ["financial_report_form", "dispatch_task"],
  "events": ["financial/form-start", "financial/form-field-update",
              "financial/form-submit", "financial/task-dispatched"],
  "component": { "kind": "financial-report-form", "version": 1 },
  "permissions": {
    "tables": ["fin_indicators", "fin_tasks"],
    "credentials": ["FIN_DB_DSN"],
    "data_scope": "user_managed_companies"
  },
  "event_namespace": "financial",
  "compensation": { "financial/form-submit": "upsert_indicators" }
```

加载校验（全部 fail-loud，启动失败即退出）：
- `name/version/domain` 格式合法；`domain` ∈ 已注册域表；
- 事件命名 `<namespace>/<entity>-<verb>`（02 §3.3）：namespace 默认取 domain，可用
  `event_namespace` 显式覆盖；namespace 全局唯一，跨插件撞名 = 启动失败；
- `events` 每个 type 的 schema 存在于 contract/ 且与词表注册不冲突；
- **重名工具/事件/组件 kind 直接启动失败**（dsh-06 D3：`index.ts:727` 同语义）；
- `compensation` 引用的动作在 backend 有实现。

## 3. 后端插件 API（`app/platform/plugins/api.py` 提供）

```python
class PluginBackend:
    name: str
    domain: str
    def tools(self, ctx: ToolContext) -> list[BaseTool]: ...
    def router(self) -> APIRouter | None: ...

class ToolContext:
    user_id: str
    session_id: UUID
    emit: EventWriter          # 追加事件的唯一通道（自动带 seq/业务id）
    resolve_credential: Callable[[str], str]   # 逐操作解析（dsh-09 B2）
    db: Session                # 受 plugin.permissions.tables 约束的 session 工厂
                               # 自带：is_delete 默认过滤、审计字段自动填充、
                               #       操作日志自动记录（02 §2.5）
```

**业务表规则（02 §2.5 三条红线）**：`models.py` 全部继承 `BusinessBase`（is_delete +
created_by/created_at/updated_by/updated_at）；禁止 DELETE，删除即 `is_delete=true`；
select/insert/update 由 db 会话自动落 `platform_operation_logs`，插件零代码。

**工具编写规则（模型只选不填，PLAN 8.4）**：
- 工具参数 schema 只含**选择**字段（公司 ids、期间、指标集 id）——数据内容字段禁止出现
  在 model_facing schema；
- 工具执行后 `emit` 事件：数据（公司列表、指标定义）由查库填充进 payload；
- 返回给模型的是摘要文本（`"已生成 Q3 填报单，覆盖 3 家公司 12 项指标"`），
  不是全量 JSON。

## 4. 域白名单与会话锁定

- `domains.yaml`：`{financial: [financial-report, ...], hr: [...]}`；
- 会话创建按 `domain` 展开插件集 → 写入 header 锁定（02 §2.1）；
- **运行中会话的工具集不可变**（dsh-06 D2：换集=回放一个模型无法继续的历史）；
- agent 装配：`create_deepagent(tools=收集(会话插件集), interrupt_before=…)`。

## 6. 《新增插件 SOP》（AI coding 的作业说明书）

1. `cp -r templates/plugin-template plugins/<name>`，改 plugin.json；
2. 写 contract 三个 JSON Schema → 跑 `gen.py` 生成双端类型；
3. backend：tools.py（选择型参数 + emit 事件 + 摘要返回）+ 业务表迁移（继承 BusinessBase
   + `attach_updated_at_trigger`）；
4. frontend：reducer（纯函数折叠事件族）+ 组件（props 用生成的 TS 类型）；
   **升级组件版本时旧版本文件保留不删**（构建清单按 `kind@version` 注册，02 §5）；
5. tests：回放测试（事件序列→断言 State）+ 工具参数合法/非法用例 + README 三问；
6. 域清单登记 → 启动验证 fail-loud 通过 → CI 绿。

**插件 README 必填三问**（dsh-12 I-3）：模型看到什么 / token 影响 / 对上下文与缓存的影响。
