# 04 · 前端设计

> 依据：dsh-01（注册/组装/回放全链路 + 源码补证不变量）、dsh-13（信任围栏/FOUC/locale/
> 零依赖原子/React 粘合收敛）；PLAN §4.2。

## 1. 壳架构（apps/frontend/src）

```
shell/            布局 · 会话列表侧栏 · 对话流视图(ChatView) · composer · 设置页
registry/         ComponentRegistry(§3) · ConversationAssembler(§4) · manifest.gen
transport/        SSEClient(重连/缓冲) · api.ts(REST) · types(来自 generated/ts)
primitives/       Button/Card/Toast/HoverCard…（零框架依赖，文案 props 外置）
state/            会话 store(Zustand) · ui store（仅壳拥有；业务组件不自建全局 store）
plugins/          （构建期引用 plugins/*/frontend，见 05 §5）
```

**纪律**（dsh-13 D）：
- 全部 React 数据流收敛到**一个 hook 构造器** `useSnapshot(source)`（对 observable 源的
  唯一绑定点，按源缓存）；
- 业务组件只 import `registry/` 与 `primitives/` 类型，不 import 壳内部模块、不 import
  其他插件——由 dependency-cruiser 进 CI 强制（与后端 import-linter 对等，07 §7）；
- README 记录已知限制与绕开方案（诚实边界，AI coding 说明书）。

## 2. 数据流（核心链路）

```
SSEClient ──帧──> ConversationAssembler.feed(event)
                    ├─ 事件族匹配(definition.match) → Context 状态机(§4)
                    └─ 普通事件 → 消息列表/工具卡片/流程条
Assembler ──节点──> ChatView 渲染（keyed by `${type}:${seq}` 或业务 id）
用户组件交互 ──REST──> 后端落事件 → SSE 回推 → Assembler 折叠（同一数据源，无前端权威状态）
刷新/重开 ──GET events 分页──> 同一 Assembler 回放 → 界面原样重建
```

**前端不持有组件权威状态**：草稿可本地缓存（乐观显示），提交以事件日志回推为准
（dsh-01 §3；PLAN 8.3）。

## 3. ComponentRegistry

```ts
interface ComponentDefinition<S> {
  kind: string; version: number
  match(event: PlatformEvent): { id: string; role: 'start'|'update'|'end' } | null
  reducer: (state: S | undefined, event: MatchedEvent) => S   // 纯函数
  component: LazyExoticComponent<Component<S & ComponentProps>>
}
interface ComponentProps {           // 框架注入
  state: S; emit: (patch) => Promise<void>   // update/submit 的 REST 封装
  disabled?: boolean; locale: Translate
}
```

规则（源码级依据 dsh-01 附）：
- `match` 只看当前事件（禁止猜最近未完成 Context）；
- reducer 返回值必非空（折叠不得丢状态）；
- 同一 `(kind,id)` 收到第二个 start / seq 非递增 / start 前出现 update → 开发态抛错，
  生产态记遥测并跳过（不变量监控）。

## 4. ConversationAssembler

职责与不变量（移植 dsh-01 源码补证）：
- 维护 `Map<contextKey, Context>` + `pending: Map<contextKey, Matched[]>`；
- **实时 append**：逐事件匹配，start→全量 replay 该 Context，update→增量 reducer；
- **历史分页 prepend**：只匹配新到事件；窗口外只有 update 挂 pending，start 补齐后批量
  兑现（分页加载不需要重扫全窗口）；
- **流式尾部隔离**：当前正在 chunk 的助手消息单独渲染路径，固化（assistant/message）
  后切换为普通气泡（避免长列表重排，dsh-01 §2.3）。

## 5. SSEClient

- `EventSource` 不可用 POST → 用 `fetch` + ReadableStream 手写 SSE 解析（沿用
  agent_harness 前端经验）；`Last-Event-Id = session:seq`；
- 断线：指数退避重连 → `GET events?after_seq=N` 补发 → `baseline` 帧恢复投影 → 续流；
  重连期间 UI 显示"重连中"，**已渲染内容不清空**；
- 事件缓冲：乱序/迟到帧按 seq 丢弃（只接受 > 已处理最大 seq）。

## 6. 壳的三个体验细节（dsh-13 直接落地）

1. **主题 FOUC**：index.html `<body>` 后内联同步脚本读 `localStorage.theme`（首访默认
   system），首帧前设置 `color-scheme` 与根 class；运行时主题服务 never touches DOM 的
   对应物：`state/ui` 持偏好，presenter 统一应用。
2. **locale 两段式**：先 `navigator.language` 临时起，登录后 Host 偏好回读活替换；
   字典查找链 `ns → common → key`（兜底 key 不白屏）。
3. **Toast/原子**：primitives 零框架依赖、文案 props 外置、`prefers-reduced-motion` 降级、
   重复消息按 per-show key remount。

## 7. 插件前端骨架（templates 落地示例）

```ts
// plugins/financial-report/frontend/index.ts
import type { ComponentDefinition } from '@/registry'   // 仅类型依赖壳
import { formReducer, FormState } from './reducer'
const FinancialForm = lazy(() => import('./FinancialForm'))

export default {
  kind: 'financial-report-form', version: 1,
  match: e => e.type.startsWith('financial/form-')
    ? { id: e.data.form_id,
        role: e.type.endsWith('-start') ? 'start' : e.type.endsWith('-submit') ? 'end' : 'update' }
    : null,
  reducer: formReducer,
  component: FinancialForm,
} satisfies ComponentDefinition<FormState>
```
