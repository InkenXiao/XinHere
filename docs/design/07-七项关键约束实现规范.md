# 07 · 七项关键约束实现规范

> PLAN v1.1 §8 的可执行化。每条：规则 / 实现位置 / 测试。

## 1. 事件版本化（02 §5 的执行细则）

- **规则**：payload 必带 `version`；只加不改；旧 renderer 永不删除；新语义用新 type。
- **实现**：`app/platform/events/registry.py` 注册 `(type, version) → pydantic 模型`；
  前端 `resolveRenderer(kind, version)` 精确匹配，缺失→GenericCard。
- **测试**：契约测试固定录一段 v1 事件序列，每次发版跑回放快照——**结果变了 = CI 失败**。

## 2. interrupt 完整生命周期

- **取消路径**：组件关闭/放弃 → `POST components/{id}/submit {action:'cancel'}` →
  落 `component/submit {action:'cancelled'}` 事件 → resume 值
  `{'action':'cancelled'}` → LangGraph 图的组件工具据此走收尾分支（返回模型
  "用户取消了本次填报"），**interrupt 永不裸挂**。
- **超时策略**：v1 显式选择"永不超时"（填报场景用户可能离开很久）；但组件 pending 状态
  在会话列表可见（`pendingInteraction` 投影）。若 M3 后需要超时，走 schedule 链路另议。
- **多中断对应**：resume 请求体必带 `interrupt_id`（后端校验与当前 pending interrupt
  匹配，不匹配返回 `INTERRUPT_MISMATCH`）——禁止隐式"回传给最近一个"。
- **测试**：cancel resume / 伪造 interrupt_id / 同会话两个组件先后中断各自恢复。

## 3. 双写一致性

```
submit 请求
  ① EventStore.append(*-submit 事件)          ← 先日志（事实源）    [事务A]
  ② 插件业务落库（fin_indicators…）            [事务B]
     失败 → INSERT platform_compensations(pending)
           + inject 一条"提交处理异常，正在重试"摘要（避免模型对已失败操作报喜）
  ③ 若 pending interrupt → Command(resume)     ← 业务落库定局后再驱动模型继续
后台 worker：轮询 pending → 按 event_seq 重放插件声明的补偿动作 → done/failed(retry++)
  补偿最终成功 → inject"补单成功"摘要；failed → inject 失败摘要并升级人工
```

顺序理由：模型可见的结论必须等业务结果定局。②③ 不可调换——补偿 worker 只能修数据，
修不了已发出的模型话术。

- **前端组件状态以事件日志为准**；本地草稿仅乐观显示，`component/submit-ack`（带
  event_seq）到达才算提交成功。
- **测试**：注入事务B失败 → 断言补偿记录生成 → worker 重放成功；kill worker 后重启幂等
  （补偿动作必须幂等，插件 SOP 强制声明）。

## 4. 模型只选不填

- 工具 schema 分区：`model_facing`（选择字段）与 `internal`（超时/呈现/权限标记）；
  `schemas()` 等价物只下发 model_facing（dsh 源码 tools/index.ts:251 同语义）。
- **CI 检查**：工具参数 schema 中出现数据内容型字段（如 `values`、`amount`）→ lint 规则
  报错（按字段名黑名单 + 人工白名单）。
- 事件 payload 的数据字段全部由后端工具查库填充；模型无法注入。

## 5. 上下文经济性

- `derive_messages` 投影 `component/submit` → 只取 `summary` 字段（02 §3.4）；
- **压缩 v1（M3）**：token 计量含 system+工具 schema+注入（全成本，dsh-05 §1）；
  阈值触发的摘要调用**逐字重放会话自身前缀**、压缩指令作为最后一条 user message 追加
  （复用 provider KV cache，dsh-05 §3 的 `buildSummarizationInput` 等价实现）；
  摘要必须比原文小否则重试；被压缩内容变 log-only，UI 可展开"查看原始明细"。
- **实现位置（双轨边界，02 §3.4）**：压缩作用于 **LangGraph 图内 state**——实现为图内
  摘要节点（移除旧消息 + 写入摘要消息），同时向事件日志落 `compaction/summary`
  （`surface_op=replace`，引用被替换 seq），保持日志可重建同一上下文；
  对账测试断言压缩后 derive_messages 投影 == 图 state。
- **注入通道**：submit 后摘要进 `user/message {source:'inject'}`——**不唤醒**新 turn
  （dsh-04 §4 inject 语义）；用户下一次发言时一起被认领。

## 6. 数据权限在工具层

- `ToolContext` 构造时绑定 `user_id`；`db` session 工厂按 `plugin.permissions.data_scope`
  预过滤（如 `user_managed_companies` → 自动加 `WHERE company_id IN (用户分管)`）；
- **前端隐藏选项只是体验，不是边界**；模型直调工具同样被过滤；
- 审计：每次工具调用事件的 payload 由后端填充，已过滤数据不落日志。
- **测试**：越权用户直调工具（绕过前端）返回过滤后结果/空集。

## 7. 契约测试 CI

| 检查 | 工具 | 失败条件 |
|---|---|---|
| schema↔pydantic↔TS 三方一致 | `gen.py --check` | 生成物过期 |
| 事件 payload 合法性 | pytest 参数化（每 type 合法/非法样本） | 校验不严 |
| 回放稳定性 | 录制事件夹具 → Assembler 快照 | 版本化破坏老回放 |
| 工具参数黑名单 | 自写 lint | model_facing 出现内容字段 |
| 分层禁令 | import-linter | plugins 互引/反向依赖 |
| 前端分层 | dependency-cruiser | 业务组件 import 壳内部模块/其他插件 |
| 业务表红线（02 §2.5） | 模型/迁移扫描 + SQL lint | 缺审计字段、缺 updated_at 触发器、出现 DELETE（含 ORM delete） |
| 操作日志覆盖（02 §2.6） | pytest（ORM 事件断言） | 业务表 select/insert/update 未落 platform_operation_logs |

## 8. 附：护栏与凭证的最小实现（随 M2/M3 带入）

  连续 ≥3/5/8 次注入升级提醒（作为 inject user message 落日志，不改 tool/result）；
  exclude 分页/记账工具且**不重置计数**；被拒绝的调用也计数。

  空白=未配置；事件/日志 schema 校验拒绝 secret 字段值（配合脱敏）。
