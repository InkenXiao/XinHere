# 03 · 接口协议设计

> 依据：dsh-08（配对/取消语义）、dsh-13 A（下行 WS/信任围栏——本平台用 SSE 简化）、
> PLAN §4.2/8.7；agent_harness `home/routes.py`（SSE 形状沿用）。

## 1. 通信总则

- **下行：SSE**（`text/event-stream`），POST + `EventSourceResponse`（沿用现有资产）。
  事件名 = 平台事件 type，data = JSON（含 seq）。
- **上行：REST POST**。SSE 断线时后台 run 不终止（StreamBridge 语义），客户端凭
  `Last-Event-Id` 重连续读（见 §3）。
- 所有响应携带 `X-Request-Id`；错误体统一 `{code, message, details?}`，code 为封闭词表
  （dsh-12 I-7：内部异常不裸奔）。

## 2. SSE 事件帧（后端 → 前端）

每帧：`event: <type>` + `data: {seq, time, ...payload}`。
**id 字段 = `session_id:seq`**（重连续读游标）。

| SSE 事件 | 载荷要点 | 前端行为 |
|---|---|---|
| `turn/start` / `turn/end` | `{turn, reason?}` | 流程边界条 |
| `step/start` / `step/end` | `{turn, step}` | 步骤计数 |
| `user/message` | `{content, source}` | 用户气泡（source=inject 折叠为"上下文注入"行） |
| `assistant/chunk` | `{turn, step, delta}` | 流式尾部追加 |
| `assistant/message` | `{turn, step, content, usage, source_event_seqs}` | 固化助手气泡 |
| `tool/call` | `{call_id, name, arguments}` | 工具卡片（running） |
| `tool/result` | `{call_id, name, content, is_error, outcome?}` + `refs:[call_seq]` | 卡片完成态；**call_id↔seq 配对由后端完成**（dsh-08：前端零配对逻辑） |
| `component/request` | `{component_id, kind, version, props, interrupt_id}` | 渲染业务组件（Lazy） |
| `component/submit-ack` | `{component_id, event_seq}` | 提交已落日志确认 |
| `projection` | `{key, value, seq}` | 服务端成品状态 last-wins（dsh-12 D1） |
| `error` | `{code, message}` | 终止帧 |

**配对规则**：`tool/result.refs` 携带对应 `tool/call` 的 seq；`assistant/message.source_event_seqs`
指向 chunk 批次——前端与回放共用同一条数据（回放 = 用 REST 拉历史事件喂同一渲染器）。

**断线重连**：客户端 `GET /sessions/{id}/events?after_seq=N`（SSE）→ 服务端先发
`baseline` 帧（当前全部投影 + pending 状态快照）再续流增量。重连期间错过的事件由
EventStore 的 seq 保证无缺口补发。

**`GET /sessions/{id}/events` 双形态**（按 `Accept` 分流，写进路由契约测试）：
`Accept: text/event-stream` → 续流模式（baseline + 增量帧）；
默认/`application/json` → 回放分页模式（JSON 数组，`?after_seq=&limit=`）。

## 3. REST 端点清单

### 会话
| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/api/v1/sessions` | `{domain}` → 创建（锁定 plugin_set，返回 header） |
| GET | `/api/v1/sessions` | 当前用户列表（分页） |
| GET | `/api/v1/sessions/{id}` | header + 统计投影 |
| POST | `/api/v1/sessions/{id}/chat` | `{message}` → SSE 流（核心端点） |
| GET | `/api/v1/sessions/{id}/events` | `?after_seq=&limit=` 事件回放分页（重连/历史） |
| POST | `/api/v1/sessions/{id}/cancel` | 取消当前 run（不删 inbox） |

并发规则（M1 定死）：同一会话已有 run 进行中时，`POST chat` 返回 `409 RUN_BUSY`
（错误码进封闭词表），前端引导用户等待或先 cancel；忙时注入（inbox 并入）语义随
M3 jobs 链路再引入。

### 组件交互
| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/api/v1/sessions/{id}/components/{component_id}/update` | `{draft}` → 落 `*-field-update` 事件（草稿，不唤醒模型） |
| POST | `/api/v1/sessions/{id}/components/{component_id}/submit` | `{values, action:'submit'\|'cancel'}` → 落 submit 事件 + resume/注入（07 §2） |
| GET | `/api/v1/sessions/{id}/components/{component_id}` | 组件当前回放态（EventStore 折叠） |

### 插件与契约
| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/v1/plugins` | 清单（name/version/domain/tools/events） |
| GET | `/api/v1/schemas/{name}.json` | JSON Schema 下发（前端构建期用，不运行时拉） |

### 反馈
| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/api/v1/sessions/{id}/feedback` | `{text}` 原文落 `feedback/record`，不解析不合并（dsh-12 G） |

## 4. Schema 单一事实源流水线（PLAN 8.7）

```
packages/contracts/schemas/*.json        # 手写：事件 payload / 工具参数 / 组件 props
  ├─ scripts/gen.py --py → generated/py/ # datamodel-code-generator → pydantic
  └─ scripts/gen.py --ts → generated/ts/ # json-schema-to-typescript → TS types
CI: gen.py --check                       # 生成物与 schema 不一致 = 失败
    + 契约测试：每个事件 type 有 payload 模型；每个工具有参数 schema；渲染器 props 与
      组件 schema 同源（import 同一 generated/ts）
```

规则：**任何一边手改生成物 = CI 失败**；schema 变更走 PR，生成物随之提交。

## 5. 安全（M1 最小集）

1. **Host 头围栏**（dsh-13 A1）：middleware 校验 Host ∈ {loopback, 配置白名单}，
   WHATWG 等价比较；`0.0.0.0` 监听在认证层就绪前禁用。
2. 用户身份：`X-User-Id` 头（对接现有网关时换 JWT），贯穿到工具层数据权限（07 §6）。
3. 上传/附件（M3）：事件只存 `attachment_ref{attachment_id, media_type, bytes,
   width, height, name?}`，四禁入（路径/blobURL/providerURL/base64，dsh-10 B1）。
