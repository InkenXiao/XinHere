# 01 · 系统架构与目录设计

> biz-agent-platform 设计文档 · 总纲。依据：PLAN v1.1 §3；dsh-12 D（settings 契约）、
> dsh-13 A（信任围栏）；agent_harness 源码（复用清单 §4）。

## 1. 总架构

```
┌────────────────────────────────────────────────────────────┐
│  apps/frontend (React 19 壳)                                │
│  对话流视图 · ComponentRegistry · ConversationAssembler      │
│  SSE 客户端(下行) + REST(上行)                ← dsh-13 A3   │
└──────────────┬─────────────────────────────────────────────┘
               │ HTTPS/SSE（开发期直连 backend:8000）
┌──────────────┴─────────────────────────────────────────────┐
│  apps/backend (FastAPI)                                     │
│  ┌──────────── app/platform（框架层，业务无关）───────────┐  │
│  │ event_store · derive_messages · plugin_loader ·        │  │
│  │ agent_service(LangGraph) · sse_hub · projections ·     │  │
│  │ settings(双层) · credentials · schema_codegen         │  │
│  └───────────────────────────────────────────────────────┘  │
│  ┌──────────── plugins/*（业务层，只依赖 platform 公开API）┐  │
│  │ financial-report: contract/ + backend/                  │  │
│  └───────────────────────────────────────────────────────┘  │
└──────────────┬─────────────────────────────────────────────┘
               │
        PostgreSQL（platform_* 表 + 业务表 + checkpointer 表）
```

**分层禁令（CI 强制，PLAN §1 原则 1/2）**：
- `plugins/*` 只准 import `app/platform` 的公开模块与 `packages/contracts` 生成物；
- `plugins/A` 禁止 import `plugins/B`；
- `app/platform` 禁止 import 任何 `plugins/*`（加载器通过清单反射发现）。
- 违反 = CI import-linter 检查失败。

## 2. 后端目录（apps/backend）

```
apps/backend/
├─ app/
│  ├─ main.py                    # lifespan：DB→插件加载→agent 装配
│  ├─ platform/
│  │  ├─ events/                 # EventStore、词表注册表、derive_messages、崩溃恢复
│  │  ├─ plugins/                # 加载器：清单解析/重名fail-loud/域白名单
│  │  ├─ agent/                  # LangGraph 装配：工具收集→create_deepagent→interrupt桥
│  │  │  ├─ executor.py          # ← 拷贝改造 agent_harness executor（§4）
│  │  │  ├─ stream_bridge.py     # ← 拷贝（SSE 断线 agent 不终止）
│  │  │  └─ event_translator.py  # ← 改造：astream_events→平台事件(含 turn/step/配对seq)
│  │  ├─ api/                    # REST 路由（03 文档端点表）
│  │  ├─ projections/            # 投影单元注册表 + worker
│  │  ├─ settings/               # 双层配置(base/user, presence语义, revision乐观锁)
│  │  ├─ credentials/            # 引用制密钥（env>file，逐操作解析）
│  │  ├─ audit/                  # 业务操作日志（select/insert/update 自动记录，02 §2.5/2.6）
│  │  └─ telemetry/              # 审计外发队列（脱敏瀑布，feedback-only 门控）
│  ├─ core/                      # 配置、日志、DB session
│  └─ persistence/               # SQLAlchemy 模型 + Alembic + BusinessBase（审计字段基类）
├─ tests/                        # 每模块单测 + 契约测试
├─ alembic/
└─ pyproject.toml                # uv 管理
```

## 3. 前端目录（apps/frontend）与 contracts

```
apps/frontend/
├─ src/
│  ├─ shell/                     # 壳：布局/对话流视图/composer/主题/locale
│  ├─ registry/                  # ComponentRegistry + ConversationAssembler
│  ├─ transport/                 # SSE 客户端/重连/事件缓冲 + REST 封装
│  ├─ primitives/                # 零依赖原子组件（dsh-13 G：零框架、文案外置）
│  └─ plugins/                   # 业务插件前端（lazy 组件 + 事件族 reducer）
└─ vite.config.ts                # 插件静态清单生成（构建时扫描 plugins/）

packages/contracts/              # 单一事实源（03 文档 §4）
├─ schemas/                      # JSON Schema：事件 payload、工具参数、组件 props
├─ generated/py/                 # → pydantic 模型（backend 用，gitignore 生成物或提交均可）
├─ generated/ts/                 # → TS 类型（frontend 用）
└─ scripts/gen.py                # 双端生成 + 一致性校验
```

## 4. agent_harness 资产复用清单

| 资产 | 处置 | 说明 |
|---|---|---|
| `execution/executor.py` | **拷贝改造** | 保留：后台 task 驱动 astream_events、StreamBridge 解耦、interrupt→component_request、resume_value→Command(resume)、断线不终止。改造：事件翻译层改为落 EventStore（seq/配对/source_seqs）、钩子改用平台事件总线、补 turn/step 事件 |
| `execution/stream_bridge.py` | **拷贝** | 内存桥，直接可用 |
| `execution/event_translator.py` | **重写** | 借鉴事件映射表形状；新增 turn/step/配对 seq |
| `execution/run_manager.py` | 拷贝 | run 生命周期映射 |
| `execution/agent_factory.py` | 拷贝改造 | create_deepagent 装配点 + 工具来自插件加载器 |
| `persistence/*` | **不搬** | 被 platform_session_events 取代（02 §2.4） |
| `observability/audit_callback.py` | 借鉴 | token 统计改走投影；审计=事件日志本身 |
| 依赖注入/宿主回调风格 | **弃用** | 改为显式构造 + FastAPI state（简单直接，团队可维护性优先） |

## 6. 部署形态（M1）

Docker Compose 两服务（frontend nginx 静态 + backend uvicorn）+ PG。
本地开发直连。**Host 头信任围栏**（dsh-13 A1：Host 校验防 DNS rebinding）写进 FastAPI
middleware，M1 实现。绑定地址不限（容器内需对 nginx 可达），但白名单只放行 loopback 与
内网主机名；认证层就绪前 backend 端口不对公网发布（compose 不映射宿主端口）。
